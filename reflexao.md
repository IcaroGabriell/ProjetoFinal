# Reflexão sobre o curso de Git e GitHub

## Antes do curso

Antes do curso, eu tinha pouco conhecimento sobre Git e GitHub. Para organizar versões de arquivos, normalmente faria cópias das pastas ou dos próprios arquivos, o que poderia gerar confusão e dificultar a identificação das alterações. Já conhecia o GitHub como uma plataforma para armazenar e compartilhar projetos, mas ainda não entendia muito bem como funcionava o controle de versões na prática.

## O que aprendi

Aprendi a utilizar o Git para acompanhar as alterações dos projetos e manter um histórico organizado do desenvolvimento. Os conceitos que mais marcaram foram o staging, os commits, as branches e a integração com repositórios remotos.

Também aprendi comandos importantes como `git add`, `git commit`, `git push`, `git pull`, `git fetch`, `git merge` e `git revert`. Entendi melhor a diferença entre trabalhar localmente e enviar as alterações para o GitHub, além da importância de utilizar mensagens claras nos commits.

## Dificuldades e como resolvi

Durante as atividades, encontrei algumas dificuldades que me ajudaram a entender melhor o funcionamento do Git.

Uma delas foi quando tentei fazer o primeiro `git push` e recebi o erro `fetch first`. Entendi que o repositório remoto já possuía um commit que ainda não estava no meu repositório local. Precisei compreender a importância de sincronizar os históricos antes de enviar as alterações.

Também tive dificuldade com alguns comandos, como o `git remote add`, inicialmente digitado sem o `git`, e com o `git clone` ao utilizar um caminho que continha espaços sem colocá-lo entre aspas.

Outro aprendizado importante foi resolver conflitos de merge. Na atividade, encontrei os marcadores `<<<<<<<` e `>>>>>>>` no README e precisei identificar as diferenças entre as versões para organizar o conteúdo corretamente.

Além disso, entendi melhor a diferença entre `git fetch` e `git pull`. Enquanto o primeiro busca as atualizações do repositório remoto sem integrá-las automaticamente, o segundo também realiza a integração dessas alterações com o projeto local.

Essas situações me mostraram que entender o motivo de um erro é mais importante do que simplesmente executar comandos sem saber o que fazem.

## O que mudou na minha forma de trabalhar

Agora entendo a importância de manter um histórico organizado das alterações de um projeto. Passei a dar mais atenção às mensagens dos commits, registrar mudanças de forma mais organizada e verificar o estado do repositório antes de executar operações.

Também compreendi a importância de utilizar branches para desenvolver funcionalidades separadamente e de revisar as alterações antes de integrá-las ao projeto principal.

## Onde vou aplicar

Pretendo utilizar Git e GitHub principalmente nos projetos desenvolvidos durante a graduação em Engenharia de Computação, especialmente nas atividades de programação e desenvolvimento de software.

Também considero essas ferramentas importantes para minha carreira profissional, pois fazem parte da rotina de desenvolvimento e permitem trabalhar em equipe, compartilhar código e acompanhar a evolução dos projetos.

## Análise crítica do curso

O curso foi importante para apresentar os conceitos de Git e GitHub de forma prática. As atividades ajudaram a entender melhor os comandos, principalmente porque permitiram experimentar situações que podem acontecer durante o desenvolvimento de projetos reais.

Acredito que um ponto positivo foi a variedade de exercícios, que abordaram desde operações básicas até situações como conflitos de merge e reversão de commits.
